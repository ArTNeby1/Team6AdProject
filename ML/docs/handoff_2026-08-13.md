## 一、后端：`/plan-itinerary` 还没接（F-09）

代码位置：`AiPlanningClientHttp.java:102` 的 `generateDailyItinerary()`

现在是写死的 STUB，直接返回空的 `days: []`，没有发任何 HTTP 请求：

```java
// 这条注释已经过期了 ↓ Python 侧 2026-08-08 就实现了
// 行程生成（F-09）还没在 Python 侧实现
return Map.of("status", "STUB", "tripId", tripId, "days", List.of());
```

**要做三件事：**

1. 把 STUB 换成真的 POST 到 `/plan-itinerary`，照同文件里 `recommend()` 的写法抄
2. 改签名 —— 现在传的是地点 ID，但 Python 侧不认识你们数据库的 ID，要先查成带
   `name`/`lat`/`lng` 的对象：
   ```java
   Map<String, Object> generateDailyItinerary(List<PlaceDto> confirmedPlaces, String startDate, int numDays);
   ```
   `PlaceDto` 跟调 `/recommend` 用的是同一个，不用另写
3. 加一个 Controller 端点，比如 `POST /api/v1/planning-sessions/{id}/plan-itinerary`，
   否则前端没有入口（这个方法现在全后端零调用点）

**请求长这样：**

```json
{
  "start_date": "2026-08-15",
  "num_days": 3,
  "places": [
    { "name": "Gardens by the Bay", "type": "attraction", "lat": 1.2816, "lng": 103.8636, "activities": ["photos"] }
  ]
}
```

**返回长这样**（`days` 长度永远等于 `num_days`，某天没地点就是空数组）：

```json
{
  "status": "OK",
  "days": [
    { "day": 1, "date": "2026-08-15", "weather_summary": "...", "stops": [ ... ] },
    { "day": 2, "date": "2026-08-16", "weather_summary": "...", "stops": [] }
  ]
}
```

`stops` 里每条的字段跟 `/recommend` 的 `ordered_stops` **一模一样**，前端 UI 能直接复用。

### `num_days` 从哪来

我今天在抽取接口加了 `duration_days` 字段，`/extract-travel-info` 和 `/refine`
的返回体现在都有：

```json
{ "destination": "Singapore", "duration_days": 3, "places": [...] }
```

后端一句话：

```java
int numDays = extraction.getDurationDays() != null ? extraction.getDurationDays() : 1;
```

文本没说玩几天时是 `null`，按 1 天兜底。**别自己从 `dates` 反推** ——
`["2026-08-09","2026-08-11"]` 是"玩3天"还是"这两天各去一次"分辨不出来。

⚠️ 另外 `PlanningService.confirmSession()` 写死了 `trip.setDurationDays(1)`，
接 F-09 时这里也要一起改，否则库里存的还是单天。

## 二、后端：地理编码还是 stub（这个影响已经接好的接口）

`MapPlacesClientStub.validatePlace()` 永远返回空 → `DraftPlace` 的 lat/lng 一直是 null
→ 传给 `/recommend` 的地点全都没坐标。

**后果**：我的距离优化（F-32 最近邻+2-opt）没有坐标就没法算，等于没跑；
F-18 推荐里"附近"那半边也用不了，只剩文字相似度。两个都不会报错，是自动降级。

**把地理编码接上，这两个立刻就有效果，AI 侧一行都不用改。**

## 三、联调怎么起服务（不用装 Ollama，不用 AWS）

```powershell
$env:EXTRACT_PROVIDER="mock"; $env:FILTER_PROVIDER="mock"; $env:RECOMMEND_PROVIDER="mock"
uvicorn main:app --reload --app-dir ML/app --port 8001
```

mock 模式下 JSON 结构跟真实模式**一模一样**，字段一个不少，而且是秒回。
调通之后把这三个环境变量去掉就切回真实模型。

## 一、候选模型：选哪 2~3 个来测，为什么

不是随便选,选之前先看这几个维度：这个模型在 Bedrock 里**是否好申请到权限**、**贵不贵**、**擅不擅长严格按格式输出 JSON**。基于这些,建议测试下面 3 个：

| 模型 | 提供方 | 为什么选它做候选 |
|---|---|---|
| **Claude 3.5 Haiku** | Anthropic | 便宜、速度快,Anthropic 家族对"严格按 JSON schema 输出"支持得好,适合当"性价比选手" |
| **Claude 3.5 Sonnet** | Anthropic | 比 Haiku 贵和慢,但理解力更强,适合当"精度上限"参照,看贵的是不是真的更准 |
| **Amazon Nova Lite（或 Micro）** | Amazon | AWS 自家模型,Bedrock 里通常最容易申请到权限、价格也很低,适合当"平台原生选手"对比一下 Anthropic 系 |

**为什么是这 3 个而不是别的：**
- 都支持 Bedrock 的 **JSON 输出模式/工具调用**（可以约束格式,不是纯靠 prompt 硬要求）,公平对比"听话程度"才有意义
- 覆盖了"贵 vs 便宜"、"Anthropic vs Amazon 自家"两个维度,结论更有说服力
- 三个的输入/输出 token 单价都不高,3 篇样本文本测下来总成本可以忽略不计（预计几美分以内）

## 二、对比维度定义

| 维度 | 怎么量化 |
|---|---|
| 听话程度（格式合规） | 模型返回的 JSON 能否直接通过 `trip_schema.json` 校验（复用 `validate_examples.py` 的校验逻辑）,3 篇样本里通过几篇 |
| 抽取准不准 | 人工核对：文本里提到的地点（places）、日期有没有被漏掉或编造,记录 漏抽数 / 编造数 |
| 速度 | 代码里对每次调用计时（调用开始到收到响应的秒数）,取 3 篇的平均值 |
| 费用 | 记录每次调用的 input/output token 数,按 Bedrock 官网单价换算成美元 |
